# 管理端 AI 原创剧本到玩家游玩

本轮补齐的是基础文字剧本的完整操作链。管理员在 `/admin` 提交标题、题材和 3–6 个角色，生成服务创作原创材料，走既有 Compiler / 模型 Audit 链路；有效审核发现警告或阻断问题后，在轮数和费用上限内修稿、以新版本重新编译与审核；管理员阅读全文、记录五维人工审核、逐项处理模型发现，分别确认和发布。玩家在 `/scripts` 选本、选角色，进入 `/play` 阅读授权私本、交换线索、询问角色、推进阶段和结算揭晓。

## 本地使用

先按 `LOCAL_SETUP_FROM_SCRATCH.md` 准备 Python 3.13、前端依赖及独立 PostgreSQL / Redis。`.env.example` 只是模板；不要覆盖已有 `.env`。

在仓库根的 `.env` 配置百炼的 `DASHSCOPE_API_KEY`、白名单模型和对应单价。沿用 `provider_config.py` 的配置检查，不接受任意 OpenAI 兼容地址。玩家对话的模型配置独立，沿用原来的角色模型与预算设置。

按原启动文档启动后端（8010）与前端（3001），另外开启一个终端，在仓库根运行：

```sh
backend/.venv/bin/python backend/scripts/creative_worker.py --allow-paid --watch
```

`--watch` 持续接收管理端新任务。省略时只处理当前队列；加 `--job-id creative-...` 只执行指定任务。服务不建表、不迁移、不创建管理员，连接的是已经配置好的数据库。首次使用需先有合法的管理员账户。

1. 点击首页“剧本工作台”。未登录、访客或失效会话会直接跳转 `/login`；工作台内容和数据请求仅在服务端确认管理员身份后加载。用管理员账号登录后进入工作台。
2. 工作台填写标题、题材和角色数，并选择自动修稿轮数和整个任务的费用上限，点击“创建生成任务”。管理端默认最多修稿2轮、上限¥0.50，可选0–3轮及¥0.20/0.50/1.00。生成服务未启动时任务保持排队，可在调用前取消。
3. 查看逐轮记录与停止原因，进入“查看最新候选与审核”，阅读全文与模型发现。每轮保留原稿、独立来源、候选及报告；无新警告或阻断问题仅表示本次模型未发现，不代表推理正确。达到上限仍有问题时转人工处理。
4. 完成人工检查后勾选五个维度，填写实际结论并保存报告。有问题可以填写带目标和来源引用的审核发现；真实内容错误应生成或导入新候选，不能用“排除误报”掩盖。
5. 对模型的每个警告或阻断问题填写独立处理理由。阻断问题只能在核实为误报后排除；所有操作由原有服务端门禁重新校验。
6. 填写最终说明，先“确认审核结果”，再“发布到玩家剧本库”。两步绑定同一候选哈希和完整审核依据，发生变化需重新读取。
7. 玩家打开 `/scripts`，选择剧本和角色，点击“以此角色开始”。进度保存于服务端，可通过首页或“我的记录”继续。

开发期可使用原来的匿名访问设置。已有玩家或管理员凭据不会被匿名登录覆盖；公开部署仍应使用独立玩家账户。

## 内容与费用边界

- 原创生成稿采用 `script-package/1.1` 的基础文字玩法，三阶段为阅读、调查、终局。调查以阶段开放物证和角色可公开材料为主；不声称新稿具有 1.4 的特殊投票、复杂胜负评分或商业剧本专属机制。
- AI 新稿作为明确标记的 `supplement` 冻结为私有来源，不伪称商业原件或人工创作。每份材料可追溯到被冻结的生成稿；来源一致性不等于语义正确。
- 来源保存在仓库外 `../private-data/import-jobs/source-bundles`；原创任务账本在 `../private-data/creative-jobs`。可分别用 `FUSION_SOURCE_BUNDLE_DIR`、`FUSION_CREATIVE_JOB_DIR` 指定仓库外的私有目录。
- HTTP 只排队，不调用模型。每轮最多一次初稿/修稿、一次编译、一次模型审核，最多初稿加3轮修稿。每次预占不超过¥0.05，开始下一轮前为3次调用预留完整额度，整个任务受管理员选定上限约束。用量未知时保留预占，异常实际费用高于预占时按实际记录并停止，不截小账单。金额取决于配置单价及供应商实际用量，不是官方价格承诺。
- 每次调用前持久化预占；未知用量保留预占，不自动重发。工作进程中断后不重跑原调用；需结合任务账本、关联编译任务和供应商账单核对，不能反复提交碰碰运气。
- 玩家资料只消费角色权限过滤后的服务端投影。未结算前不向玩家发送系统真相；其他角色的秘密不会放入剧本目录或开场资料。
- 开局和游戏请求使用幂等键。网络错误或 5xx 后保留原请求并阻止新操作，显式“核对原请求”复用原键；刷新后仍可恢复待核对请求。服务端 4xx 拒绝可按提示纠正或刷新进度。
- 后端不可用会显示实际错误，不会自动混入演示剧本、人物或线索。

## 验证与限制

离线验证在独立临时副本、临时 SQLite 和模拟模型中完成，不连接用户数据库，不读取密钥，不产生真实模型费用。

```sh
backend/.venv/bin/python backend/scripts/test_fusion_security.py
backend/.venv/bin/python -m unittest discover -s scripts -p 'test_dev_preflight.py'
cd frontend
npm test
npm run check
npm run build -- --webpack
```

新增后端覆盖排队幂等、并发工作进程互斥、取消、付费开关、格式失败、人数不符、未知用量、权限控制，以及生成到发布和选角结算的链路。前端测试覆盖身份保持、恢复不依赖剧本列表、重复挂载、错误状态、动作格式和原请求重放。

生产构建使用 Webpack 通过；当前执行环境禁止 Turbopack 内部监听端口，`npm run build -- --webpack` 可避开该环境限制。字体使用系统字体，不依赖远程字体请求。

本轮没有验证真实模型的内容质量与账单、真实 PostgreSQL 并发、生产部署、手机实体设备或短信服务。上线前仍需用原创小样本进行真实生成、逐角色试玩并检查证据链。原有 `runtime_ready=false` 未被修改为上线就绪。
