# 原创剧本自动修稿与复审

2026-10-30，面向管理端新建原创剧本。保留现有 FastAPI / Next.js / PostgreSQL 基座、正式发布门禁、旧候选和游戏存档，不运行真实模型或改动付费设置。

## 使用流程

1. 管理员在 `/admin` 填写标题、题材和3–6个角色，设置自动修稿轮数及整个任务的费用上限。
2. 创作服务生成初稿，冻结私有来源，再编译候选并执行模型审核。
3. 有效审核报告包含 `WARNING` 或 `BLOCKER` 时，修订编辑接收完整原稿、完整报告、报告目标对应的候选条目，修订相关内容。`INFO` 保留展示，不触发修稿。
4. 修稿保存为独立稿件，冻结新来源，以 `ai-v2`、`ai-v3` 等新内容版本执行新的编译和审核任务。模型不能修改或清除旧报告。
5. 没有新的警告或阻断问题时停止自动循环，交管理员阅读全文、检查五个维度、处理发现、确认审核结果，再显式发布。
6. 达到轮数、预算不足、稿件无变化、输入过大、格式失败或用量未知时停止，展示原因和已产生的版本。没有自动回退供应商或重复调用。

管理端默认最多2轮修稿、总上限¥0.50。可选择0–3轮和¥0.20 / ¥0.50 / ¥1.00。这里是配置的硬限额与保守预占规则，不是供应商价格承诺，也不表示质量已验收。

`CLEAN_AUDIT` 仅表示该次模型未报告警告或阻断问题；它不是人工审核通过或发布批准。正式发布仍完全走原门禁。默认查看最终候选，历史版本也可回看；管理员若单独选择历史候选发布，仍须针对该版完成全部人工审核、处置和显式确认。

## 实现与兼容

- `creative_generation.py` 的新任务标为 `creative-revision/1.0`，新增 `current_round`、`rounds` 和 `stop_reason`。
- 每轮记录稿件指纹、改动范围、来源指纹、子任务与候选ID、审核摘要/全部发现/报告指纹和费用。完整原稿只写入私有任务目录的 `drafts/`，不会放进列表、Git或公开静态目录。
- 每次修稿是一个新请求，而非失败重试。每个模型调用前先持久预占，SDK不重试；进程中断后的原任务拒绝重跑，必须人工核对。
- 每轮开始前为初稿或修稿、编译、审核三次调用留足最多¥0.15。子任务执行前，父记录先保存¥0.10完整额度；子任务终结后再按已知用量或未知预占结算。仍排队/运行的子任务保留完整预占，不能少报。
- 修订保留角色人数、姓名和顺序。原稿、报告和候选条目均按非可信素材处理；修订输出不能传入批准、发布或工具调用字段。
- 修稿输入超过24 KiB时停下，不丢弃审核发现凑输入长度。复杂或长报告需要管理员处理。
- HTTP只创建任务。`creative_worker.py --allow-paid --watch` 仍须管理员独立启动；本轮没有启动付费worker、填写密钥或开启模型费用开关。
- API未传新参数时 `max_revision_rounds=0`、`cost_ceiling_cny=0.20`，兼容旧客户端；管理端显式传默认2轮/¥0.50。旧任务没有新工作流标记时仍走原单轮逻辑，幂等比较补齐默认值但不改写旧文件。
- 无需新增数据库表或迁移。每轮继续复用既有不可变候选、来源核验和审核账本。

## 状态

| 状态/停止原因 | 含义 |
| --- | --- |
| GENERATING / COMPILING / REVISING | 初稿、编译与审核、自动修稿中 |
| COMPLETED + CLEAN_AUDIT | 本次未发现警告或阻断问题，等待人工审核 |
| REVIEW_REQUIRED + ROUND_LIMIT | 到达修稿上限，仍需人工处理 |
| REVIEW_REQUIRED + BUDGET_LIMIT | 剩余额度不足下一轮，停止新增调用 |
| REVIEW_REQUIRED + NO_CHANGE | 修订稿与上一稿相同，停止重复修改 |
| BLOCKED + PIPELINE_BLOCKED | 格式、来源、角色一致性或其他确定性检查未通过 |
| NEEDS_RECONCILIATION + RESULT_UNKNOWN | 调用/用量未知、中断或其他worker仍可能执行，保留预占待核对 |
